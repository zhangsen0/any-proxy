## 为什么归档

这个项目已经完成了它的周期：需求全部交付、测试全绿、部署上线并验收通过。
归档（archive）意味着**停止活跃维护**，而不是删除 —— 代码、文档、提交历史全部保留，
只是不再接受新的 issue 和 PR。

### 本轮踩到的两个环境坑（与项目代码无关，但很费时间）

1. **`git push` 报成功，远端分支却没变**。这台机器的 git 连 `refs/remotes/*` 都写不进，

### 本轮踩到的环境坑（与项目代码无关，但很费时间）

1. **PAT 失效 + GitHub MCP 未加载**。推送用的 PAT 直接返回 `401 Bad credentials`；
   GitHub MCP 在会话里是 `disabled: true`，工具列表里根本没有它。两条路同时堵死时，
   先确认哪条还能用，别在同一条上重试十次。
2. **Python 的「直连」其实也走代理**。`urllib` 不传 `ProxyHandler` 时会读 Windows 注册表里的
   系统代理 —— 于是「代理挂了就改直连」是假动作，两条路径报的是同一个错。
   禁代理必须显式写 `ProxyHandler({})`。
3. **本地 esbuild 压出来的名字 ≠ wrangler 压出来的名字**。`ReferenceError: o is not defined`
   里的 `o` 是 wrangler 自带 esbuild 分配的，本地怎么压都复现不出来。要验产物，
   就得拿**真正会部署的那一份产物**去验。
4. **云沙箱里 `github.com` 被网络策略拦掉时，不要拿 PAT 去喂公共镜像**。这类环境的表现是
   `github.com` 解析到一个假 IP（如 `198.18.0.14`）、TLS 握手被中断。这时搜到的各种
   「GitHub 加速镜像」能读不能信：拿一个空 token 去问 `api.github.com/user` 也会返回一个
   别人的账号 —— 说明它在替你带身份，你的 PAT 同样会被它看到。
   正解是**走自己的节点**：订阅里拿 vless 节点 → 本地起 Xray（SOCKS5）→
   `git -c http.proxy=socks5h://127.0.0.1:1080 push`，DNS 在远端解析，假 IP 也绕过去了。

### 这一轮**没做**的事（有意留着的）

延迟实测目前**只接了一处**（自动优选 DNS 更新时按快慢排序，且默认关闭）。
三个更有感的落点留给下一轮：订阅下发的节点按快慢排、代理上游「换路」替代「补发」、
节点健康检查按延迟淘汰 —— 它们都依赖同一份带 TTL 的延迟缓存，先做其中一个，
另外两个就能复用，不必三个一起上。

## 第五轮：订阅排序 + 浏览器测速真正参与优选（2026-09-18）

**触发**：一句追问 ——「浏览器自动优选有用吗，以现在的逻辑」。

**查出的事实**：两处延迟能力都只兑现了一半，而且是**同一个病根** —— 排序用的数字
不是从用户网络量出来的。关键证据是一次对照实验：同批 24 个 IP（服务端已排好序的订阅里
取前 12 + 后 12），换两个网络各测 3 次取中位 ——

| 测量起点 | 前 12 中位 | 后 12 中位 | 差距 |
|---|---|---|---|
| 沙箱直连 | 687 ms | 814 ms | 127 ms（有区分度） |
| 经用户节点（美国出口） | 727 ms | 738 ms | 11 ms（等于没排） |

两组排序的斯皮尔曼相关系数 **rho = −0.056**（近似零相关）。结论：服务端排出来的「最快」，
换一个网络看基本是随机顺序。另外还发现 `http://<IP>/__api/config` 的耗时里混着 Worker
冷启动（同一 IP 裸 https 握手失败只要 0.10 s，走 http 探活却要 0.56 s），连「纯网络延迟」
都算不上。

**两笔提交**：`709cff6` 把快慢排到订阅上（客户端通常拿第一个节点）；
`81a2737` 让浏览器测速结果真正参与自动优选 —— 浏览器定「谁快」，服务端只定「谁通」。

| 步骤 | 做了什么 |

### 第五轮的一条设计决定（值得单独记）

**不再让服务端排快慢。** 服务端只能回答「通不通」，快慢交给能从用户网络测量的那一侧：
订阅场景退而求其次用服务端数字（冷启动噪声 + 视角偏差都在，但至少把不通的垫了底），
自动优选场景改用浏览器实测值。两者都不假装「服务端测出来的快 = 用户感觉到的快」。

**已知边界**：开着代理访问面板时，浏览器测到的是「出口节点 → CF」而不是「你 → CF」，
此时数值会全挤在一起 —— 代码只能**识破并提示**（`spread()` 判极差与相对离散度），
没法根治，因为浏览器拿不到「如果不走代理会多快」。

## 第六轮：wrangler.toml 去写死 + 长表单切页（2026-09-18）

**触发**：两句反馈 ——「wrangler.toml 有写死的，能不能改成可配置的」；
「现在有的 tab 页相当长，需要优化一下，或者加 tab 页，或者可以折叠不常用的」。

**查出的事实**：

- 写死的有五个：`database_id`（本项目账号下的 D1）、KV `id`、R2 `bucket_name`、
  `name`、`GH_ACTIONS_URL`（指向原仓库）。前三个确实是**部署形态**项，必须写在
  wrangler.toml 里，面板改不动也不该改 —— 但「必须写在文件里」不等于「必须写死某个
  账号的值」。fork 后不改就部署失败，而 wrangler 的报错里没有任何线索指向这个文件
  （上一轮写部署文档时只能把它标成「第 3 步 · 最容易漏」，能写文档让人照做的就该自动做掉）。

  折叠了，剩下的基础项仍是一长条，找一项要在滚动条里来回来去。

### 第六轮的两条设计决定（值得单独记）

**一、能写文档教人照做的，就该自动做掉。** 「把 ID 抄进 wrangler.toml」这一步，
文档写得再清楚也只是把负担转嫁给读文档的人。改成占位符 + 部署前渲染之后，
fork 完不用改任何文件，也不用去控制台抄 ID；想复用已有资源时才需要填 Variables。

**二、判据要验「那个进程当时看到的输入」，不能只验最终结果。** 这次事故里，
脚本最后写出来的文件是对的、自己的日志也是绿的，唯独中间那一步（另一个进程）读到的是旧的。
所以自检里塞了一个假 `npx`，把「迁移那一刻磁盘上的文件」抄下来直接验 ——

**已知边界**：自动创建资源依赖 `CLOUDFLARE_API_TOKEN` 有建库 / 建命名空间权限；
没有就明确报错并给出两种解决办法，不会静默跳过。R2 是唯一允许失败的资源 ——
账号没开通时删掉绑定降级，其余功能不受影响。

## 第七轮：浏览器优选口径可配 + 面板「返回主页」按钮保活（2026-09-18）

**触发**：两句 —— ①「浏览器自动优选的来源在哪里，可以自定义吗」；
②「代理管理面板 返回主页的按钮没了」。

**查出的事实**：

- 浏览器自动优选「怎么跑」的五个数字**写死在页面脚本里**（一次测 40 个、留 15 条、
  并发 8、单次超时 3500、拉候选超时 9000）。于是把「订阅候选上限」从 40 调到 100，
  浏览器那边**依旧只测 40 个** —— 面板上有开关、行为不变，不报错、不抛异常。
  与第六轮 wrangler 那次是同一类病：「能改的地方」和「真正生效的地方」不是同一个。
- 「返回主页」按钮：注入函数本身没坏（三种 HTML 形态都注入成功，`inject.js` 这几轮
  都没碰过）。真正成因是它只是一段被塞进 HTML 的 `<a>`，而 edgetunnel 面板是 SPA，
  一重绘 DOM 就把它抹掉 —— **并且这条功能此前没有任何一条自检覆盖它**。

**两笔提交**：`5d791da`（测速口径收进运行参数）→ `6dae568`（按钮注入 + 保活）。

| 步骤 | 做了什么 |
|---|---|
| 1 | 仓库 Settings → Unarchive |
| 2 | 列清浏览器优选链路上所有写死数字，确认「订阅候选上限调了不生效」这个真 bug |
| 3 | `5d791da`：新增 `pick_scan_limit / pick_keep / pick_concurrency / pick_timeout_ms / pick_candidate_timeout_ms`（默认值与旧行为一字不差）；新增 `pickLimits(cfg)` 统一下发；两条接口都回带；前端照单执行 |
| 4 | CI 全绿后收到按钮反馈 → 定位为 SPA 重绘抹除，且无任何自检覆盖 |
| 5 | `6dae568`：注入改为「HTML + 保活脚本」（按钮不在就补回，MutationObserver 盯重绘，幂等）；样式只定义一份 |
| 6 | `check-rewrite` 17 → 25（把保活脚本抠出来在最小 DOM 桩上真跑）；`check-preferred` 7 → 24 |
| 7 | 跑全量离线自检（20 套，**1043** 项）+ `gen-manual.mjs --check`；牙齿验证七处 |

### 第七轮的两条设计决定（值得单独记）

**一、拿不到口径就停，不用写死数字兜底。** 兜底一份等于又造一套真源，
「看起来能跑」比「明确报错」危险得多。同理，拉订阅**失败**那个出口也要回带口径 ——
失败后前端还要走「当前池」兜底，只在成功分支带就是「只在失败时才出问题」。

**二、没有检查覆盖的功能，等于可以悄悄消失。** 按钮存在了大半年，重绘一抹就没了，
20 套自检没有一条报警。补检查时也不只验 HTML 产物，而是把保活脚本抠出来在最小 DOM 桩上
真跑：清空节点模拟重绘 → 调 observer 回调 → 断言补回来了。（详见 [07-踩坑记录 第 21 条](./07-踩坑记录.md)。）

**已知边界**：伪装开启时**刻意不注入**返回主页按钮 —— 那时 `/` 是伪装页，
按钮既没用、又是面板存在的活招牌。伪装开着时看不到它是设计如此，不是 bug。

## 归档后：还能做什么 / 不能做什么

| | 归档后 |

cron、优选、健康检查、伪装全部照旧。只有当 Secrets 过期或要改配置时才需要解除归档。
