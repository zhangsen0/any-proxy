# 05 · 部署上线

## 流水线三步

```
push → master
  ↓
① verify.yml            8 个自检脚本（unit job）+ 浏览器 e2e
  ↓  必须全绿
② deploy-cloudflare.yml Workers 部署（Secrets 注入 + backend 裁剪）
  ↓
③ healthcheck.yml       健康检查 + 自动修复
```

`deploy` 和 `healthcheck` 之间是 `workflow_run` 关系 —— 这个细节引发过一次事故，见下一节。

---

## 为什么不要绕过 CI 直接 `wrangler deploy`

本地也可以用 CF API Token 直接部署，**但不建议**：

GitHub Actions 在部署时会注入一批 Secrets 和变量：

```
PASSWORD            UUID
CLOUDFLARE_API_TOKEN
DISGUISE_PATH       DISGUISE_TOKEN         ← 伪装的进门凭据
STORAGE_BACKEND                             ← 决定 wrangler.toml 保留哪个 binding
PROXY_HOST                                  ← 健康检查的目标域名
```

直接用 wrangler 部署会用本地 `wrangler.toml` 的配置，**这些注入项一个都没有** ——
结果是伪装进门凭据丢失（等于把自己锁在门外）、存储后端绑定错。

**规则**：要走 CI。除非明确知道自己在做什么，并且能接受重新配一遍所有 Secrets。

## 上线后怎么验收

按顺序跑，前三条不过就别往下走。

### 1. 伪装是否收敛（最高优先级）

```bash
curl -s https://<你的域名>/ | grep -o "<title>[^<]*</title>"
# 期望：伪装模板的标题，比如「站点维护中」

# 页面内不该出现任何面板痕迹
curl -s https://<你的域名>/ | grep -c "__admin\|__api\|Any-Proxy"
# 期望：0

# 敏感路径一律 404，而不是 302
for p in /__admin /__api/sites /admin; do
  curl -s -o /dev/null -w "$p -> %{http_code}\n" https://<你的域名>$p
done
```

> 特别检查有没有 **302**。返回 302 到登录页会把 `/__admin` 这类命名空间写进
> `Location` 头，伪装就白做了。

### 2. 两种进门方式

```bash
curl -s -o /dev/null -D - https://<你的域名>/site-status | grep -i "location\|set-cookie"
# 期望：302 + Set-Cookie: visited=1

curl -s -o /dev/null -D - "https://<你的域名>/?k=<你的口令>" | grep -i "set-cookie"
# 期望：同样下发 visited
```

带 cookie 再访问根路径应当能看到管理面板。

### 3. 反代与压缩

```bash
curl -s -D - -o /dev/null https://<你的域名>/p/<站点id>/ \
  -H "Accept: text/html" -H "Accept-Encoding: gzip" | grep -i "content-encoding"
# 期望：gzip
```

### 4. 订阅链路与国家标注

```bash
SUB_URL=https://<你的域名>/tsub/<id>
curl -s "$SUB_URL" -o /tmp/sub.txt
python3 tools/check-nodes.py /tmp/sub.txt
# 期望：绝大多数节点达到 L4
```

## 回滚

Workers 没有「一键回滚到上个版本」的按钮，所以：

- 出问题优先**用新代码修**（小改动跟着 CI 走，几分钟）
- 实在要退回，回到目标 commit 重新走一遍 push → verify → deploy

这也是为什么每次改动要保持小粒度、commit message 要写清楚为什么（见
[03-开发规范](./03-开发规范.md) 第 8 条）—— 回滚时你需要在几分钟内定位到该回哪个 commit。

## 上线检查表

```
□ 本地 8 个自检脚本全绿
□ CI 的 verify job 全绿（unit + e2e）
□ deploy job success
□ 验收 1：伪装收敛，无 302 泄露
□ 验收 2：两种进门方式都能拿到 visited
□ 验收 3：反代页面正常，Content-Encoding: gzip
□ 验收 4：订阅能拉到，节点多为 L4
```
