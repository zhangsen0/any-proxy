# 06 · 运维与自愈

## 健康检查怎么自愈

`healthcheck.yml` 做的事，按顺序：

1. 解析优选目标域名的 **A 记录**
2. **A 记录读不到就 `exit 1` 并报错** —— 这是本轮加的守卫，原因见下面的事故
3. 记录/更新当前生效的 IP
4. 发现失效则触发修复

同时 cron 每 5 分钟触发一次（实际自动优选按前端配置的间隔执行，默认 12 小时）。

---

## 一次真实事故：假健康

**现象**：每次 push 都是绿的，看起来一切正常。

**真相**：`PROXY_HOST` 仓库变量漏配，健康检查在第一个守卫处就失败、直接退出；
而 e2e 校验因为是 `workflow_run` 触发、在这次场景下被跳过。于是形成了：

```
每次 push 都绿  →  但自愈链路从没真正跑过
```

**根因不是代码问题，是配置缺失 + 断言太软**：那时 healthcheck 即使读不到 A 记录也不报错，
Token 失效会被当成「健康」默默过去。

**修了两条**：

1. A 记录读不到时 `exit 1` 并给出明确错误，不再沉默
2. `PROXY_HOST` 缺失时给出**明确报错**（「无法确定优选目标域名：请配置 PROXY_HOST」），
   而不是猜测域名或用写死的兜底

这两条都有自检覆盖：

```
✅ dns-run 缺少凭据时立即报错 — HTTP 500｜缺少 CF_API_TOKEN / CF_ZONE_ID Secret
✅ dns-run 未陷入长时间等待 — 3ms
✅ cron 无 PROXY_HOST 时可用已记住的域名兜底
✅ cron 且无历史域名时给出明确错误（不猜域名）
```

---

## 教训：断言要敢失败

这次事故的核心教训不是「忘了配变量」，而是**监控在自己失效时选择了沉默**。

一个在自己出问题时默不作声的健康检查，比没有健康检查更危险 —— 它提供的是虚假的安全感。
同理适用于：

- 抓不到日志时不假装无事发生
- 依赖的服务挂了要报出来，不要降级成「可能正常」
- 「可能是网络抖动」不能当作默认结论（虽然它确实是理由之一，但要验证过才敢这么说）

## 日常要看什么

优选相关的最小检查：

```bash
# 优选链路自检（订阅候选能否拉到、探测会不会超时）
SUB_URL=https://<你的域名>/tsub/<id> node tools/check-preferred.mjs

# 离线模式（不联网，只验证规则与预算）
CIDR_FILE=./cidrs.txt SKIP_NETWORK=1 node tools/check-preferred.mjs
```

预算相关的断言是重点 —— **优选必须在 Workers 的 30 秒墙钟内跑完**，
超时会被直接掐断，一个候选都写不回去。自检里的断言是：

```
✅ 优选探测阶段留在预算内 — 2503ms < 15000ms
```

## 线上出问题怎么查：`wrangler tail` 之外的一条路

排障最容易卡在第一步：**拿不到日志**。本机 `npx wrangler tail` 经代理访问 npm 镜像会握手失败
（`ERR_SSL_SSLV3_ALERT_HANDSHAKE_FAILURE`），而且它对已经过去的请求也无从回溯。
这时候可以直接问服务端 —— 运行时状态的单一真源存储本身（本项目的默认后端是 **D1**，不是 KV）。

下面这几段命令都是**只读**，可以放心敲：

```bash
CF="<你的 CF API Token>"; ACC="<你的账户 ID>"

# 1) 找刚刚到底往哪儿写了 —— 别猜，列出来
curl -s --socks5-hostname 127.0.0.1:1080 \
  "https://api.cloudflare.com/client/v4/accounts/$ACC/d1/database" \
  -H "Authorization: Bearer $CF" | jq -r '.result[] | "\(.uuid)  \(.name)"'

# 2) 表里有哪些键（这一步常常就能看出「缓存攒没攒起来」）
D1="<上一步的 uuid>"
q(){ curl -s --socks5-hostname 127.0.0.1:1080 -X POST \
  "https://api.cloudflare.com/client/v4/accounts/$ACC/d1/database/$D1/query" \
  -H "Authorization: Bearer $CF" -H "Content-Type: application/json" \
  -d "{\"sql\":\"$1\"}" | jq -r '.result[0].results[] | "\(.key)\t\(.value)"'; }

q 'SELECT key, length(value) AS len FROM kv ORDER BY key'

# 3) 看某个开关现在的值（面板说「已保存」不等于运行时读的是它）
q "SELECT key, value FROM kv WHERE key IN ('NODE_COUNTRY_TAG','APP_CONFIG')"
```

> **访问 api.cloudflare.com 必须走代理**（直连会返回空导致 JSON 解析失败），
> 所以上面都带了 `--socks5-hostname`。这一条本身就是踩过的：空响应被当成 JSON 解析，
> 报出来的错跟真正的问题毫无关系。

### 一次真实排查（订阅下载不下来）

症状是 `/sub?token=…` 时好时坏，坏的时候 `HTTP 503 + error code: 1102`。
**1102 是 Cloudflare 平台层的墙钟超时**，不是业务代码返回的错误 —— 这句话决定了排查方向：
不去找「哪里抛了异常」，而去测「到底慢在哪一步」。

| 观测手段 | 拿到了什么 |
|---|---|
| `curl -w '%{http_code} %{time_total}'` 连打 8 次 | 上线前稳定 **17 秒**；修完 **2.7~3.3 秒**、8/8 全部 200 |
| 解码订阅内容数 unique IP | **67 个唯一 IP，且每次拉取集合还不同** → 延迟缓存永远攒不起来 |
| 直接 POST 外部 geoip 接口 | 1.3 秒正常返回，排除第三方依赖故障 |
| 查 D1 的 `LATENCY_CACHE` | 修复前为空/过期；修复后有 **108 条** → 证明限量那一刀真的生效了 |
| 查 D1 的 `NODE_COUNTRY_TAG` | **`false`** —— 备注没国家标注是**面板里被关掉的**，不是代码回归 |

最后一条尤其重要：**看到「功能没生效」别默认就是回归**。先问「这个开关现在的值是多少」，
一次查询就能区分「写错了」和「被人关了」。同理，也可以从 `APP_CONFIG` 里直接看到面板存的运行参数。

## 凭据管理

凭据要选**最小作用域**的 API Token，并且定期轮换 —— 不要用一个万能 token 打通所有环节。

本项目需要的 Cloudflare 凭据分两类：

| 用途 | 建议 scope |
|---|---|
| Workers 部署 | Workers 的编辑权限（限定账户） |
| DNS / 优选探测 | Zone 的 DNS 编辑权限 |
| R2（可选） | Object 读写（限定 bucket） |

轮换时只需更新 GitHub Secrets，**不要把 token 写进 `wrangler.toml`** —— 那文件在版本库里。
`wrangler.toml` 的注释里也专门写了：敏感项（隐蔽路径 / URL 口令）建议走 Actions Secrets。
