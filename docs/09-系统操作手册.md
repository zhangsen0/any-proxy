# 09 · 系统操作手册

> 这份手册面向**使用者**，不面向改代码的人。按「我要做什么」组织，每一步都能照着点完。
> 想看设计取舍与实现细节，去 02-架构设计；想知道为什么某处这么绕，去 07-踩坑记录。

## 0. 这份手册怎么用

- **第一次部署**：读第 1 章，照抄即可。
- **不知道某个功能在哪**：读第 2 章（选项卡导览），五分钟能建立全图。
- **正在做具体一件事**：直接跳第 3 章的对应小节。
- **遇到报错或异常**：跳第 5 章，按症状查。
- **查字段名 / 默认值 / 环境变量 / 接口路径**：查附录 A（由代码自动生成，永远与实现同步）。

一条贯穿全篇的原则：**能在面板里改的，就不要去改代码或环境变量**。
面板配置存在存储里，保存即生效；环境变量只是首次部署的种子（见第 4 章）。

## 1. 第一次上线

### 1.1 需要准备什么

| 东西 | 说明 |
|---|---|
| Cloudflare 账号 | 免费套餐够用 |
| 一个接进 Cloudflare 的域名 | 用于自定义域名与 DNS 优选（可选，但强烈建议） |
| D1 数据库 或 KV 命名空间 | 二选一，默认 D1。用来存站点配置、各功能的面板配置 |
| GitHub 仓库 | 部署走 Actions，push 即上线 |

数据库与 KV 的绑定写在 `wrangler.toml` 里，**绑定名不要改**（`SITES` 是代码里写死要找的名字）。

### 1.2 上线步骤

1. 在 Cloudflare 建好 D1 数据库（默认名 `any-proxy-db`），把 `database_id` 填进 `wrangler.toml`。
2. 在 GitHub 仓库的 **Settings → Secrets and variables → Actions** 里配置 Secrets（至少 `CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`、`PASSWORD`）。
3. `git push origin master`。
4. Actions 会自动：按 `STORAGE_BACKEND` 裁剪 `wrangler.toml` → 应用数据库迁移 → 部署 Worker → 写入 Secrets。
5. 等 Actions 跑完（Verify + Deploy 两步都绿），访问你的域名，看到登录页就成功了。

> 表结构由 `migrations/0001_init.sql` 定义，部署时自动应用，不需要手动执行 SQL。

### 1.3 三个地址，记住就行

| 地址 | 作用 |
|---|---|
| `https://<你的域名>/__login` | 登录入口。**开了首页伪装之后，这个地址会先要求走隐蔽路径** |
| `https://<你的域名>/__admin` | 管理面板。所有配置都在这里 |
| `https://<你的域名>/p/<站点后缀>/...` | 反代访问入口，一个站点一个前缀 |

其余保留路径（不要拿来做站点后缀）：`/p/`、`/sub`、`/tsub/`、`/edt`、`/admin`、`/__`、以及临时链接的默认前缀 `/s`。

### 1.4 首次登录后，建议先做三件事

1. **改口令并配好隐蔽入口**：`伪装与安全` 选项卡 → 首页伪装 → 设一个隐蔽路径（例如 `/mypanel`）和进门口令。
   不开伪装也没关系，但一旦对外，这一步决定了别人能不能猜到这是个代理面板。
2. **加一个站点**：`站点` 选项卡 → 填名称和网址 → 保存。立刻就能通过 `/p/<后缀>/` 访问。
3. **配优选与通知**（可选但推荐）：
   - `优选 IP` 选项卡 → 填订阅链接 → 点「浏览器自动优选」→ 「保存优选池」；
   - `告警通知` → 填 Webhook → 点「发一条测试告警」确认能收到。

## 2. 界面导览：每个选项卡管什么

面板顶部一排选项卡，**一块功能只有一个归属地**。这条规矩是有代价换来的：
优选池曾经同时长在「优选 IP」和「配置」两页里，改完一边忘了另一边就会出现
「面板显示 A、实际生效 B」，排查起来极费时间。

| 选项卡 | 管什么 | 不该在这里找什么 |
|---|---|---|
| **站点** | 反代站点的增、删、改、复制链接 | 其他功能的开关 |
| **代理节点** | 订阅链接、节点国家标注、通往代理面板与临时订阅页的入口 | 优选 IP 的配置 |
| **优选 IP** | 自动优选频率、立即优选、优选 IP 池、**候选域名池与健康检查**、浏览器自动优选 | 站点设置 |
| **伪装与安全** | 首页伪装的模板、文案、隐蔽路径、进门口令、严格模式 | — |
| **外观主题** | 10 套内置主题、自定义主题、自动轮换 | 页面内容 |
| **临时链接** | 临时链接的开关与默认值、生成、停用、删除 | — |
| **配置** | 只放**没有独立选项卡**的设置：访问统计、限流防滥用、告警通知；外加诊断工具，以及通往上面各页的入口 | 站点/主题/伪装/优选 的配置表单（都在各自页里） |

「配置」这一页现在很短，这是刻意的：它只做两件事 —— 摆开没人管的设置，以及当索引。

## 3. 日常操作

### 3.1 加一个反代站点

**站点** 选项卡 → 名称 + 网址 → 保存。

- **访问后缀**留空会自动生成（由名称推出来）；自己填要避开 1.3 里那串保留段。
- 加完就能用 `https://<你的域名>/p/<后缀>/` 打开目标站，站内链接、CSS、JS 都会被自动改写。
- 改后缀会让旧链接失效，面板上会有提示。
- 删除站点后 `/p/<后缀>/` 立即失效，没有回收站。

### 3.2 节点与订阅

**代理节点** 选项卡：

- **订阅链接**：浏览器优选从这里拉候选 IP。留空则回退到本机 `/sub`。
  第三方订阅常混入非边缘网络的节点，系统会按 Cloudflare 官方 IP 段先过滤再测速 —— 不过滤的话，
  那些不可达地址会占满优选池，还会把「立即更新优选 IP」拖到超时。
- **节点国家标注**：给订阅里的节点备注补上归属国家，主订阅与临时订阅都生效。
  国家查询结果长期缓存，同一个 IP 只查一次；数据源挂了会自动跳过标注，**绝不影响订阅本身**。
- **代理面板** 与 **临时订阅管理**：这两个是独立页面，通过选项卡里的链接跳过去。
  临时订阅给的是独立 UUID，到期自动失效，适合临时分享。

### 3.3 优选 IP 与 DNS

**优选 IP** 选项卡，按顺序理解：

1. **自动更新频率**：定时任务多久跑一次优选（5 ~ 1440 分钟，默认 720 = 12 小时）。
2. **立即更新优选 IP**：不等周期，马上测通并改写 A 记录。
3. **订阅链接**：候选 IP 的来源。
4. **优选 IP 池**：真正的候选列表，每行一个 IPv4。保存只存列表，**不**动 DNS。
5. **浏览器自动优选**：从订阅拉候选，在**你自己的浏览器**里并发测速（约 5~15 秒），最快的自动填进池子。
   之后再点「保存优选池」。为什么放浏览器测：出口在你那边，测出来的延迟才是你真正会遇到的。
6. **优选池 & 健康检查**：
   - 上方显示**已验证可用集**（健康检查与自动优选优先使用的 IP）；
   - 下方是**候选域名池** —— 当优选池不够用时，解析这些域名拿到当前 CF 泛播 IP 再扫描可用性。
     保存后即时生效，不需要重新部署。

**健康检查**由 GitHub Actions 每 12 小时跑一次，发现 A 记录指向 1034 或不可达时，
从可用集里自愈。Actions 页可以手动触发「Health Check & Auto Repair」。
（面板里若显示了触发链接，直接点即可。）

### 3.4 首页伪装

**伪装与安全** 选项卡。启用后，没通过隐蔽入口的访客访问根路径 `/` 只会看到一个普通站点页面。

- **隐蔽路径**：进门地址。设了之后 `/__login` 也会先要求走它。
- **进门口令**：URL 里带的口令，用来给浏览器打上「进门标记」。
- **模板**：极简维护页 / 企业官网 / 文章列表 / 下载页 / 自定义 HTML。选「自定义」就整页直出你贴的 HTML。
- **严格模式**：未登录时连 API 数据都拿不到（返回伪装 404）。**对外一定要开。**
- 想自查访客视角，用面板里的「预览伪装页」；浏览器带着进门 cookie 时看到的是真面板，
  这个按钮就是用来绕过自己身份的。

### 3.5 外观主题

**外观主题** 选项卡：

- 点任意色卡即可切换（只影响你这台浏览器）；想让所有访客都用这套，点「设为全站默认」。
- **自动轮换**：三种方式 —— 关闭、每次访问随机、按时轮换（同一时刻所有人看到的是同一套）。
  可以指定参与轮换的主题池，留空 = 全部。
- **自定义主题**：只写要覆盖的 CSS 变量（如 `--accent`、`--bg`、`--font`、`--radius`），其余自动继承。

登录页在伪装开启时**刻意不套主题**，保持中性外观 —— 免得登录页的配色本身成为识别特征。

### 3.6 站点临时访问链接

**临时链接** 选项卡：

1. 上方是开关与默认值：启用、链接前缀、默认有效期、最长天数、默认次数上限、是否记录访问次数。
2. 下方选站点 + 天数 + 次数 → 「生成链接」。
3. 列表里可以直接复制、停用、启用、删除。

**有效期与访问次数任一先到即失效。** 计数与到期判定都在服务端做 —— 写进链接里的东西可以被伪造。

### 3.7 访问统计

**配置** 选项卡 → 访问统计。

- 打开「启用统计」后，按天记录各通道的请求数与流量，用来回答「最近谁在用什么」。
- 实现上是**内存里聚合、按间隔批量落盘**，不逐请求写存储，所以开着也不拖慢代理。
- 「记录来访者数」只存来访 IP 的哈希，不存原始 IP。
- 想看数据：同一张卡下面的「工具 → 查看统计数据」，可以指定天数。
- 保留天数是硬上限，超期数据自动清理。

### 3.8 限流与防滥用

**配置** 选项卡 → 限流与防滥用。

日常只需要三个字段：**启用**、**窗口内允许请求数**、**时间窗**。
`已登录的请求不限流` 建议保持开启，否则自己用面板时会被自己的阈值挡住。

其余在「进阶选项」里：放行名单（IP / CIDR）、豁免路径、屡犯封禁的阈值与时长。
**如果启用了限流，记得把登录接口加进「豁免路径」**，否则登录页自己会被限流挡掉。

要点：

- 计数在**每个实例的内存**里做，是「单实例级平滑限流」，不是全局精确计数 ——
  限流是防滥用，不是计费，为绝对精确加一次存储往返会把每个正常请求都拖慢。
- **封禁记录会落盘**，跨实例生效，可以在同一张卡的「工具」里查看当前封禁、一键解封。
- 改动生效有几秒的收敛延迟（实例内有短暂缓存），属正常现象，不是没保存上。

### 3.9 告警通知

**配置** 选项卡 → 告警通知。

1. 填 **Webhook 地址**，选推送格式（通用 JSON / 企业微信机器人 / 钉钉机器人）。
2. 打开「启用告警」。
3. 点同一张卡「工具 → 发一条测试告警」，走完整发送链路（绕过冷却），确认通道真的通了。
4. 收不到时看「查看最近发送记录」—— 里面记着每次的跳过原因（冷却中、超出每小时配额、未订阅该事件），
   排查「为什么没收到」先看这里。

注意两点：

- **Webhook 地址是敏感项**：面板只回显「是否已配置」，不发明文。想改就重新填，留空表示不动。
- **同一事件有冷却**（默认 30 分钟），并且有每小时发送上限（默认 20 条），避免一次故障刷爆你的群。
- 不订阅任何事件 = 全部订阅。

## 4. 配置放在哪、优先级是什么

每个配置项都按同一套三级取值：

```
面板配置（存在数据库里）  →  环境变量（首次部署的种子）  →  默认值（写死在模块里）
```

含义：

- 在面板里存过 → 永远以面板为准，环境变量被忽略。
- 没存过 → 用环境变量的值，并且**第一次读取时会写回存储**，之后就可以在面板里维护了。
- 都没配 → 用模块里明写的默认值。这些默认值都是与业务无关的中性值，
  项目里没有「取不到就悄悄用一个别人的域名/IP」这种兜底。

所以：**想重置某项配置，就在面板里改成想要的值，不要去删数据库**。
环境变量改了不会立刻生效 —— 面板里已有值时它不参与判断。

各字段对应的环境变量名，见附录 A。

## 5. 出问题怎么查

### 5.1 症状对照表

| 症状 | 多半是什么 | 怎么办 |
|---|---|---|
| 打开域名看到的是一个普通网站 | 首页伪装在生效，你还没进门 | 用隐蔽路径进一次门，或登录后再看；面板里可用「预览伪装页」自查访客视角 |
| `/__login` 打开是 404 | 同上，伪装开启时未进门一律伪装 404 | 先走隐蔽路径 |
| 登录后 API 全返回 401 | 没有登录态，或换了浏览器 | 重新登录；严格模式下未登录拿不到任何数据是设计如此 |
| `/p/<后缀>/` 打开 502 | 目标站不可达，或目标站不允许被反代 | 看面板的错误提示；换目标站验证，或确认上游是否拦了非浏览器请求 |
| 页面能开但样式/图片丢了 | 目标站用了绝对路径或 CDN 域名 | 先确认是不是目标站自身的限制；重写规则是通用规则，不做站点特判 |
| 站点列表能看，但改不动 | 未登录（只读视图） | 登录后重试 |
| 限流开了，自己也被挡住 | `已登录的请求不限流` 关了，或登录接口没进豁免路径 | 配置 → 限流 → 打开登录豁免 / 把登录路径加进豁免路径 |
| 登录页自己返回 429 | 登录接口没在豁免路径里 | 同上；也可先「解除全部封禁」 |
| 面板显示保存成功，但行为没变 | 配置有 3 秒实例内缓存，或只改了环境变量 | 等几秒再试；确认改的是面板而不是环境变量 |
| 收不到告警 | 通道没通 / 冷却中 / 未订阅该事件 | 看「最近发送记录」里的跳过原因；先发测试告警 |
| 优选 IP 一直不更新 | 候选域名池为空、或订阅链接失效 | 看优选页的提示；检查订阅链接与候选域名池 |
| 域名解析到 1034 / 打不开 | 优选 IP 失效 | 健康检查会在下个周期自愈，也可点「立即更新优选 IP」 |
| 临时链接打不开 | 到期了，或次数用完了，或已被停用 | 面板列表里能看到状态；重新生成一条 |

### 5.2 能自己跑的验证

在仓库里（本地）可以直接跑自检，不需要连云：

```bash
node tools/check-smoke.mjs       # 功能组合起来还通不通（改链路后必跑）
node tools/check-configui.mjs    # 配置页与代码是否一致（改配置项后必跑）
node tools/check-themes.mjs      # 主题
node tools/check-guard.mjs       # 限流 / 告警 / 临时链接
node tools/check-disguise.mjs    # 伪装
```

想在本地把整个面板点一遍：

```bash
node tools/local-dev.mjs 8787
# 管理页 http://127.0.0.1:8787/__admin  口令 dev
```

要在**已部署的实例**上验证：

```bash
node tools/check-live.mjs https://<你的域名> <口令>
```

它会跑完主题、防护与配置接口，并在结束时把改过的配置恢复原样。

## 6. 什么能在线改，什么要重新部署

| 想改的东西 | 怎么做 |
|---|---|
| 站点、订阅链接、优选池、伪装、主题、限流、告警、临时链接 | **面板里改，保存即生效** |
| 功能开关的初始值（首次部署） | 环境变量 / GitHub Secrets |
| 页面结构、接口、算法 | 改代码 → push → Actions 自动部署 |
| 数据库表结构 | 改 `migrations/` → push，部署时自动应用 |
| 登录口令 | GitHub Secrets 里的 `PASSWORD`，改完需要重新部署一次 |

一句提醒：**敏感项（口令、Webhook 地址、进门口令）一律不要在面板之外的公开渠道传**，
面板本身也不会回显它们的明文。
