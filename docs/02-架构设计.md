# 02 · 架构设计

## 为什么是 Cloudflare Workers

整套东西跑在一个 Worker 上，不是一个应用 + 一组服务。选择它有三个约束条件倒逼出来的理由：

1. **隐匿性**：没有固定 IP、没有自家服务器能被人顺着账单或备案追到，对外只有分布式的边缘节点
2. **成本**：代理/订阅请求是突发型的，为峰值常备机器不划算
3. **位置**：优选 IP 这件事要求探测者本身就在边缘网络上，Workers 天然在那儿

代价也很清楚，并且贯穿所有设计：**约 30 秒墙钟上限、约 10ms CPU 预算（免费计划）、无文件系统、
强隔离（isolate 之间不共享内存）**。下面几乎每个决策都能追溯到其中某一条。

## 模块地图

```
worker.js              入口，把请求交给 router
└─ src/router.js       路由分发 + 访客分档 + 伪装判定（301 行）
   ├─ disguise.js      伪装页渲染、三档访客模型、模板（471 行）
   ├─ proxy.js         反向代理核心：转发 / 重写 / WebSocket 透传（518 行）
   │  ├─ url.js        URL 与内容的改写规则（274 行）
   │  ├─ inject.js     前端钩子脚本注入，运行时兜底（1248 行）
   │  └─ compress.js   出口响应定稿（一律明文，编码协商交给边缘）
   ├─ subs.js          主订阅生成（285 行）
   │  └─ nodetag.js    给订阅节点备注补国家（263 行）
   │     └─ geoip.js   IP 归属查询：批量 + 永久缓存 + 零数据表（308 行）
   ├─ tempsubs.js      临时订阅（独立 UUID + 有效期）（127 行）
   ├─ dns.js           DoH 解析 + 优选探测（386 行）
   ├─ admin.js         管理面板（1596 行，最大的一个模块）
   ├─ config.js        配置文档读写 + SPEC + 环境变量种子 + 缓存
   ├─ settings.js      运行参数注册表：面向运营的参数唯一真源（面板表单与运行时共同消费）
   ├─ config-ui.js     配置表单的通用渲染器（按注册表出控件，支持分段）
   ├─ api-catalog.js   接口目录：面板渲染与操作手册附录的共同来源
   ├─ auth.js          登录态（163 行）
   ├─ sites.js         站点配置读写（133 行）
   ├─ runtime.js       KV / D1 的统一存储抽象（14 行）
   └─ vendor/vless.js  edgetunnel 协议实现（6699 行，第三方，原则上不改）
```

**边界原则**：`vendor/` 一行不改。节点由 vless.js 生成，所有增强都在**出口**做（订阅发出前加工），
上游升级时不冲突，关掉开关就是原样透传。这条原则让后续几次升级都没动过 vendor。

## 三档访客模型

这是伪装功能的骨架，也是最容易理解错的地方：

| 档位 | 判据 | 根路径看到什么 |
|---|---|---|
| 陌生人 | 无 `visited` cookie | 伪装模板页（如「站点维护中」） |
| 已进门未登录 | 有 `visited`，无登录态 | 登录页 |
| 已登录 | 有登录态 | 管理面板 |

进门有两种方式：**隐蔽路径**（`DISGUISE_PATH`）或 **URL 口令**（`DISGUISE_TOKEN`），
两者都在 exist 之后才生效，命中后下发 `visited` cookie。

**安全兜底**：就算两个 Secret 都丢了也不会被锁死在门外 —— `/__login` 始终匿名可达。

## 配置驱动的三级降级

```
面板配置（KV/D1）  →  环境变量种子  →  SPEC 默认值
```

这一条是写死的纪律：**不允许悄悄回退到任何写死的域名 / IP / IP 段 / 版本号**。
默认值本身也必须是中性值（不含任何具体部署的域名与口令），并且和校验规则放在同一处声明。

听起来很啰嗦，但它救过一次场。`PROXY_HOST` 仓库变量漏配时，健康检查在第一个守卫处失败、
e2e 又因为是 `workflow_run` 触发被跳过，结果是「每次 push 都是绿的，自愈链路从没真跑过」。
如果用写死的兜底，这个故障会伪装成健康继续藏着，直到某天真出事才发现自愈从来没通过电。
详见 [06-运维与自愈](./06-运维与自愈.md)。

## 配置统一化：能配的都搬到面板上

原先配置有两条互不相通的入口：面板管一部分（站点、统计、限流、告警、伪装…），
另一部分**只认环境变量**（`env.SUB_STRICT`、`env.PROXY_HEDGE_MS`、`env.CF_API_TOKEN`…）。
后者的问题不是「没做界面」，而是改了要**重新部署才生效**，面板上又看不到它 ——
运营者只能翻 `wrangler.toml` 猜线上到底在跑哪个值。

现在全部收进 `src/settings.js` 的 `SETTINGS_SPEC`，一处声明三处消费：

| 消费方 | 怎么用它 |
|---|---|
| 运行时 | `readSetting(env, key)` / `readSettings(env)`，取值仍走三级降级 |
| 面板表单 | `api-catalog.js` 的目录项带 `spec/params`，`config-ui.js` 按注册表渲染控件，**不手写表单** |
| 操作手册 | `tools/gen-manual.mjs` 从同一份生成速查表附录 |

加一个可配置项 = `SETTINGS_SPEC` 加一条（+ 目录里挂上），界面与手册自动跟随。
`tools/check-single-source.mjs` 静态钉住「别处不许出现 `env.XXX` 直读」，
`tools/check-settings.mjs` 端到端真跑一遍「渲染 → 保存 → 立即生效」。

**保存即生效**：写库后 `writeSection` 调 `notifyConfigChange(section)` 广播，
各模块在 `onConfigChange` 里清掉自己的进程内快照（`cf-analytics.js` 的 `cache.clear()`、
`geoip.js` 的 `cfNets = null`），因此下一次请求就按新值跑，不需要重新部署。

**留在环境变量里的只剩两类**，都是部署形态而非运营参数：

- 绑定与后端：`STORAGE_BACKEND / DB / SITES / MEDIA_R2` —— 改它等于换存储，必须与 `wrangler.toml` 的绑定同改；
- 进站口令与引擎密钥：`PASSWORD / KEY` —— 是凭据而非配置，混进 KV 只会多一处泄漏面。

## 存储

双后端可选，运行时由 `runtime.KV` 统一抽象：

- **D1（默认）**：关系型，适合多条件查询
- **KV（可选）**：键值，延迟更低

部署时按 `STORAGE_BACKEND` 裁剪 `wrangler.toml`，只保留实际使用的那个 binding。

## 反向代理的正文链路

这是性能优化的重点理解对象：

```
浏览器 → Worker
       → 向上游发请求（Accept-Encoding: identity，必须拿明文才能改写）
       → 读 body → 按实际字符集解码 → 改写（URL / 注入钩子）
       → ★ 压缩 → 浏览器
```

第 `★` 步是本轮补上的。在它之前，解开的明文直接发出去，几百 KB 的 bundle 全裸奔。

**为什么必须向上传 identity**：内容一旦被改写，body 已解压，头上的 `content-encoding`
就成了谎言，浏览器按压缩去解明文会导致全部资源解析失败。所以解密这一步躲不掉，
只能在出口重新压回去。

**哪些响应不压缩**：已压缩过的、二进制（`image/` `video/` `zip` 等）、流式
（`text/event-stream`，一压就会被缓冲住，实时性直接没了）、小于 512 字节的。

## 订阅链路

```
/sub（主订阅）   /tsub/<id>（临时订阅，独立 UUID + 有效期）
   ↓ 生成节点（vendor/vless.js）
   ↓ nodetag.js：提取 host → 批量查 GeoIP → 改写备注
   ↓ 维持进出编码形态一致（base64 进就 base64 出）
   → 客户端
```

国家查询的设计（详见 [01-需求与迭代](./01-需求与迭代.md) 迭代 3）核心是批量 + 永久缓存 +
负缓存 + 零数据表。任播兜底用 Cloudflare 官方 IPv4 段做纯内存 CIDR 匹配，
段列表拉取一次长期缓存，之后零外部请求。

---

## 优选链路

候选来源多级降级（详见读写 README「优选是怎么跑的」）：

```
已验证可用集 GOOD_IPS → 优选池 PREF_IPS → 订阅链接里的节点 → 候选域名池动态解析
```

**预算机制**：单次优选有总时间预算（默认 22000ms，须小于 Workers 30s 墙钟）。
因为 Workers 到点就掐，宁可少测几个候选也要保证能把结果写回去。
