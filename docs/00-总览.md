## 一句话背景

一套跑在 Cloudflare Workers 上的统一代理：反向代理任意站点 + VLESS 节点订阅 +
自动优选 IP，共用一套 Cloudflare 资源和一个管理面板，对外还有一个可伪装的首页。

一份配置只允许有一个可改的地方：每个功能都归到唯一一个选项卡，
面板里没有「同一项在两处都能填」的情况，免得改完这边忘了那边。
所有非部署形态的运行参数（阈值 / 上限 / 开关 / 外部接口地址 / 凭据）收在 `src/settings.js`
的一张表里，面板表单、运行时取值与操作手册附录全部由它生成 —— 加一个参数只改一处，
改完保存即生效，不必重新部署。

## 快速上手顺序

- **还没部署**：读 [11-新手部署手把手](./11-新手部署手把手.md)，照着点完就有自己的节点了。
- **只想用起来**：读 [09-系统操作手册](./09-系统操作手册.md)，按「我要做什么」找。
- **要接手维护**：按 **07 → 02 → 05** 的顺序读。先看踩坑记录，因为那些坑一旦踩上
  就是几小时；再看架构理解为什么这么设计；最后看部署，别照着错的产物上线。
