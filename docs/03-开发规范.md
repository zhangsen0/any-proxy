# 03 · 开发规范

通用规范（命名、提交信息格式之类）这里不重复，只写**这个项目特有的、
违反了就会出事**的几条。每条都配了实际踩过的反例。

---

## 1. 处理含非 ASCII 的文本，禁止直接用 `atob` / `btoa`

`atob` / `btoa` 只认 Latin-1。订阅里含中文备注是常态，直接用会两处崩：
解码出乱码、编码时直接抛 `InvalidCharacterError`。

```js
// ❌ "vmess节点" 会变成 "vmessèç¹"
atob(b64);

// ✅ 走 UTF-8
new TextDecoder().decode(Uint8Array.from(atob(b64), c => c.charCodeAt(0)));
```

本项目已抽出 `b64DecodeUtf8` / `b64EncodeUtf8`（在 `nodetag.js`），所有涉及订阅 / vmess JSON
的路径都必须走它。

**代价提醒**：这不是「显示不好看」级别的问题，它会**毁掉整份订阅**。

---

## 2. Response body 一旦读取就 locked

任何「读了 body 之后又决定不处理」的分支，都必须按原文重建响应。

```js
// ❌ 读过再返回这个 response，客户端拿到空壳
const text = await upstream.text();
if (跳过处理) return response;

// ✅ 重建
return new Response(text, { status: response.status, headers: response.headers });
```

订阅处理那条链路专门抽了 `passthrough(resp, original, status)` 来统一处理这种分支。

---

## 3. 改函数签名时，必须顺着调用链往上检查

这是本项目唯一一次让生产环境全站 502 的原因 —— `proxyRequest` 加了 `env` 参数，
中间层 `dispatchProxy` 没跟着传：

```
ReferenceError: env is not defined   ← 每个代理页面 502
```

当时的情况是：`rewrite` / `compress` / `disguise` 的单测**全绿**，因为它们都没走完整链路。
这类问题只有集成测试抓得住，因此后来补了 `tools/check-smoke.mjs`，
刻意从 `handleRequest` 进入而不是直接调某个内部函数。

**规则**：跨模块改了签名，就跑一遍 `node tools/check-smoke.mjs`。

---

## 4. 缓存 key 必须带命名空间

两份缓存如果处理分支不同、产物不同，就绝不能用同一个 key。

```js
// ❌ cachedHtmlRewrite 与 cachedDocWritePage 用了完全相同的 key
const key = `${site.id}|${crossHost}|...`;
// 结果：同一 URL 被导航请求访问后，Turbo 的局部更新会拿到一整份 docWrite 包裹的文档

// ✅
const key = `rw|${site.id}|...`;   // rewrite 分支
const key = `dw|${site.id}|...`;   // docWrite 分支
```

---

## 5. 候选 IP / 配置绝不能写死兜底

见 [02-架构设计](./02-架构设计.md) 的「三级降级」。允许的路径只有三条：
面板配置 → 环境变量种子 → **`SETTINGS_SPEC` 里的中性默认值**。

写死一个域名或 IP 段当兜底，短期看是「更健壮」，长期看是把故障伪装成健康。
默认值也不许夹带任何具体部署的信息（域名、IP、口令一律不许出现在 `settings.js`）。

---

## 5.5 面向运营的参数：一处声明，三处消费

判据不是「代码里有没有常量」，而是「**同一个设定有没有两份定义**」。

新增一个运营参数（阈值、上限、开关、外部接口地址…）时，正确做法只有一条：

```js
// src/settings.js —— 加一条 SETTINGS_SPEC
my_new_limit: {
  type: 'int', default: 20, min: 1, max: 200, env: 'MY_NEW_LIMIT',
  group: 'preferred', label: '我的新上限', unit: '个',
  hint: '为什么需要它 / 调大调小的后果',
},
```

然后在 `api-catalog.js` 把它的 key 挂到某个目录项的 `params` 里。界面、手册、运行时自动跟随。

**禁止**：
- 在模块里直读 `env.MY_NEW_LIMIT`（唯一例外是 `settings.js` 自己作为种子的兜底）——
  `check-single-source.mjs` 会静态扫出来变红；
- 在模块里再抄一份 `|| 20` 之类的默认值——需要默认值就 `readSetting(env, 'my_new_limit')`；
- 手写表单控件——`config-ui.js` 按注册表渲染，字段的 `min/max/value` 全部插值。

改完必须**即时生效**：如果你的模块有进程内缓存（`let cache = null` 这种），
就必须挂一个 `onConfigChange` 钩子把它清掉，否则用户改完面板值、请求仍走旧快照。
（先例：`cf-analytics.js` 的 `cache.clear()`、`geoip.js` 的 `cfNets = null`。）

回归检查：`node tools/check-settings.mjs`（端到端真跑「渲染 → 保存 → 立即生效」）。

## 6. 压缩相关：动了 body 就要动 header

这是本项目最容易被后来的改动踩坏的一条。凡是把解压后的明文往外发的地方，必须：

```js
headers.delete('content-encoding');   // 否则浏览器按 gzip 去解明文 → 全站 JS/CSS 崩溃
headers.delete('content-length');     // 长度已经变了
```

反过来，凡是要保留压缩的就一个字都不能动。补 br/brotli 支持时尤其小心——
**Workers runtime 不提供 brotli 编码器**，只有 gzip / deflate。

---

## 7. 并发

Workers 有 CPU 预算，并发不是免费的：

- 大 body 的 `arrayBuffer()` 要设上限（本项目：HTML 3MB、其它 512KB，超过直接透传）
- 订阅 TEXT 超过 512KB 不加工
- 对外请求统一带 `AbortSignal.timeout()`，且总预算小于 30s 墙钟
- 重试之间**不要 sleep** —— sleep 期间 Worker 照样占 CPU 预算

---

## 8. 提交信息的粒度

一个 commit 一件事，且 body 里写清楚**为什么**。坏的例子是「fix bug」，
好的例子是项目里这条：

```
fix(check-nodes): L4 判据失效，导致健康节点被误判成「转发无回包」

- 字节串与字符串混用：b"101" not in <str> 直接抛 TypeError，
  调用方的 except continue 把它吞了，全部节点显示成 "WS ok 但转发无回包"
- 每个探测目标改为新开一条连接
```

半年后排查问题时，后者的价值是前者的十倍。
